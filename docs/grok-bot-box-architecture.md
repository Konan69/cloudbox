## 1. Topology: what runs where

### The shortest accurate model

The shipped design is not “Electron directly SSHs into a VM.” Electron main owns credentials, settings, the remote-box broker connector, recovery, VNC trust, and a child coordinator. The coordinator talks HTTP/SSE to a gateway exposed by a **host process inside the box**. That host runs the agent/session system and talks over loopback Connect/protobuf RPC to the box execution daemon. A separate desktop-local execution daemon exists only for tools that intentionally act on the user’s own computer. The coordinator is a separate Electron utility-process child. Electron main forks `node-agent-coordinator/main.cjs`, creates three `MessageChannelMain` channels (control, renderer data, and main data), transfers one endpoint of each to the child, and owns restart/backoff if the child exits. [`source/electron-main/coordinator/coordinator-launcher.ts:38-70`](../../refs/grok-bot-0.18-reconstructed/source/electron-main/coordinator/coordinator-launcher.ts#L38-L70) [`source/electron-main/coordinator/coordinator-runtime.ts:104-166`](../../refs/grok-bot-0.18-reconstructed/source/electron-main/coordinator/coordinator-runtime.ts#L104-L166)

The coordinator is a relay and lifecycle boundary, not the agent runtime. It resolves a gateway descriptor from Electron main, keeps a gateway SSE stream, dispatches renderer/main RPC requests to the host, supervises the desktop-local exec daemon, forwards MCP OAuth and WebAuthn work, and starts the gateway client. The host is the long-lived in-box application server. It starts its extension graph, starts or reuses an exec daemon, exposes health/commands/events/local-exec/WebAuthn through its HTTP gateway, writes gateway discovery, and shuts all of those pieces down together. ### What is a “box”?

From the client’s perspective, a remote box is a backend-assigned **tenant/pod with a host gateway, exec-daemon endpoint, VNC endpoints, and tokens**. `EnsureSandBoxRequest` has no agent or conversation fields, while its response contains `cluster`, `tenant_id`, `pod_id`, network/exec tokens, exec URL, VNC URLs, terminal folder, and gateway URL/token. [`source/packages/proto/generated/aiserver/v1/sand_box_pb.ts:940-962`](../../refs/grok-bot-0.18-reconstructed/source/packages/proto/generated/aiserver/v1/sand_box_pb.ts#L940-L962) [`source/packages/proto/generated/aiserver/v1/sand_box_pb.ts:996-1119`](../../refs/grok-bot-0.18-reconstructed/source/packages/proto/generated/aiserver/v1/sand_box_pb.ts#L996-L1119)

The code does **not** establish whether the remote pod is a full VM, a container, a microVM, or some nested combination. The backend scheduler, hypervisor/container runtime, image supervisor, resource sizing, and host installation mechanism are **unknown/not reconstructed**. The strongest safe wording is “backend-assigned pod/box.” The local substitute is definitively a Docker container despite the UI calling it a “VM.” [`source/electron-main/box/local-docker-host-connector.ts:13-17`](../../refs/grok-bot-0.18-reconstructed/source/electron-main/box/local-docker-host-connector.ts#L13-L17) [`source/electron-main/box/local-docker-host-connector.ts:183-203`](../../refs/grok-bot-0.18-reconstructed/source/electron-main/box/local-docker-host-connector.ts#L183-L203)

The box is not per conversation. The desktop asks the broker for `ensureSandBox({})` with no agent ID; the host then wraps one underlying box under the fixed shared ID `shared` and maps many agent IDs to separate display indices in it. File upload/download ignore the caller’s agent ID and target that shared box. [`source/electron-main/box/box-host-connector.ts:81-99`](../../refs/grok-bot-0.18-reconstructed/source/electron-main/box/box-host-connector.ts#L81-L99) [`source/host/box/shared-desktop-sand-box.ts:11-18`](../../refs/grok-bot-0.18-reconstructed/source/host/box/shared-desktop-sand-box.ts#L11-L18) [`source/host/box/shared-desktop-sand-box.ts:32-36`](../../refs/grok-bot-0.18-reconstructed/source/host/box/shared-desktop-sand-box.ts#L32-L36)

An “agent” is also the durable conversation/session identity in this host. Agent directories are keyed by agent ID, contain `store.db`, and `session.id` is passed as the box ID for shell/browser/computer-use setup. [`source/host/extensions/session/session-paths.ts:7-12`](../../refs/grok-bot-0.18-reconstructed/source/host/extensions/session/session-paths.ts#L7-L12) [`source/host/extensions/session/agent-session.ts:95-131`](../../refs/grok-bot-0.18-reconstructed/source/host/extensions/session/agent-session.ts#L95-L131) [`source/host/host-runner-composition.ts:1020-1089`](../../refs/grok-bot-0.18-reconstructed/source/host/host-runner-composition.ts#L1020-L1089)

### Ownership and lifecycle

**Create/attach.** Electron main owns the broker call and account-scoped gateway descriptor. `connect()` calls `ensureSandBox({})`; the returned gateway URL/token and VNC proxy data become the coordinator connection. A safe-storage-encrypted desktop cache is scoped to the signed-in account and expires after seven days, but it is refreshed against the broker. [`source/electron-main/box/box-host-connector.ts:74-102`](../../refs/grok-bot-0.18-reconstructed/source/electron-main/box/box-host-connector.ts#L74-L102) [`source/electron-main/box/gateway-descriptor-cache.ts:7-21`](../../refs/grok-bot-0.18-reconstructed/source/electron-main/box/gateway-descriptor-cache.ts#L7-L21) [`source/electron-main/box/gateway-descriptor-cache.ts:91-145`](../../refs/grok-bot-0.18-reconstructed/source/electron-main/box/gateway-descriptor-cache.ts#L91-L145)

**Run/attach agent.** On demand, the host waits for exec-daemon readiness, assigns an agent a display, and returns a remote resource accessor plus VNC URL. In the shared-desktop wrapper, all agents use the same underlying `shared` box and get fork windows when available. [`source/host/box/loopback-sand-box.ts:35-42`](../../refs/grok-bot-0.18-reconstructed/source/host/box/loopback-sand-box.ts#L35-L42) [`source/host/box/shared-desktop-sand-box.ts:20-32`](../../refs/grok-bot-0.18-reconstructed/source/host/box/shared-desktop-sand-box.ts#L20-L32)

**Release agent.** Releasing an agent tears down only that agent’s fork window assignment and reports the agent’s box status absent; it does not destroy the shared underlying box or shared filesystem. [`source/host/box/shared-desktop-sand-box.ts:34-36`](../../refs/grok-bot-0.18-reconstructed/source/host/box/shared-desktop-sand-box.ts#L34-L36) [`source/host/extensions/forever-box/host-box.ts:18-22`](../../refs/grok-bot-0.18-reconstructed/source/host/extensions/forever-box/host-box.ts#L18-L22)

**Pause.** “Client pause” is a desktop feature gate, not a VM suspend primitive. It refuses new connector operations, tells the coordinator to pause its gateway client, drops the observed egress connection, and retires the desktop-local exec daemon. Resume re-enables gateway resolution and respawns/reconnects local exec. [`source/electron-main/box/box-client-pause.ts:18-62`](../../refs/grok-bot-0.18-reconstructed/source/electron-main/box/box-client-pause.ts#L18-L62) [`source/node-agent-coordinator/gateway/gateway-client.ts:203-215`](../../refs/grok-bot-0.18-reconstructed/source/node-agent-coordinator/gateway/gateway-client.ts#L203-L215) [`source/node-agent-coordinator/local-exec/supervisor.ts:330-359`](../../refs/grok-bot-0.18-reconstructed/source/node-agent-coordinator/local-exec/supervisor.ts#L330-L359)

**Hibernate.** The protobuf exposes `ABSENT`, `HIBERNATED`, and `RUNNING`, and admin RPC descriptors include hibernation, but the normal reconstructed host `hibernate()` methods are no-ops. The backend’s idle hibernation trigger, resume policy, billing behavior, and GC/destruction schedule are **unknown/not reconstructed**. [`source/packages/proto/generated/aiserver/v1/sand_box_pb.ts:19-59`](../../refs/grok-bot-0.18-reconstructed/source/packages/proto/generated/aiserver/v1/sand_box_pb.ts#L19-L59) [`source/host/box/loopback-sand-box.ts:44-44`](../../refs/grok-bot-0.18-reconstructed/source/host/box/loopback-sand-box.ts#L44-L44) [`source/host/box/shared-desktop-sand-box.ts:33-33`](../../refs/grok-bot-0.18-reconstructed/source/host/box/shared-desktop-sand-box.ts#L33-L33)

**Recreate/reset/update.** Remote update/reset is a broker RPC with `preserve_data` and `force`. A successful response supplies an optional migration operation ID; preserve-data false is the reset path and true is the update path. [`source/packages/proto/generated/aiserver/v1/sand_box_pb.ts:1121-1228`](../../refs/grok-bot-0.18-reconstructed/source/packages/proto/generated/aiserver/v1/sand_box_pb.ts#L1121-L1228) [`source/electron-main/box/box-host-connector.ts:102-118`](../../refs/grok-bot-0.18-reconstructed/source/electron-main/box/box-host-connector.ts#L102-L118)

**Migrate.** Electron watches a backend migration stream with phases `backing-up → creating → moving → cleaning-up` or `wiping`, then `done/failed`. It resumes from an offset key, reconnects every 3 seconds, treats 30 seconds as a stall, and gives up after 20 stall reattachments. [`source/electron-main/box/box-migration-watcher.ts:9-19`](../../refs/grok-bot-0.18-reconstructed/source/electron-main/box/box-migration-watcher.ts#L9-L19) [`source/electron-main/box/box-migration-watcher.ts:30-77`](../../refs/grok-bot-0.18-reconstructed/source/electron-main/box/box-migration-watcher.ts#L30-L77) The backend mechanics behind those phases are **unknown/not reconstructed**.

**Recover.** Recovery composes the migration relay with recreate commands and a coordinator restart hook. Independently, the coordinator automatically relaunches after process exit, and its gateway transport reconnects with backoff. [`source/electron-main/box/box-recovery.ts:12-67`](../../refs/grok-bot-0.18-reconstructed/source/electron-main/box/box-recovery.ts#L12-L67) [`source/electron-main/coordinator/coordinator-runtime.ts:124-166`](../../refs/grok-bot-0.18-reconstructed/source/electron-main/coordinator/coordinator-runtime.ts#L124-L166) [`source/node-agent-coordinator/gateway/gateway-client.ts:393-413`](../../refs/grok-bot-0.18-reconstructed/source/node-agent-coordinator/gateway/gateway-client.ts#L393-L413)

**Quiesce/resume agent work.** Before a recreate, the host suspends automation wakes, marks active work for durable resume, reports agent IDs and pending cloud/shell wakes, then can resume those agents after reconstruction. Background shell processes explicitly do not survive recreate; the resumed agent receives an interruption notice. [`source/host/host-gateway-api.ts:584-598`](../../refs/grok-bot-0.18-reconstructed/source/host/host-gateway-api.ts#L584-L598) [`source/host/extensions/transcript/upgrade-recreate-resume.ts:184-221`](../../refs/grok-bot-0.18-reconstructed/source/host/extensions/transcript/upgrade-recreate-resume.ts#L184-L221) [`source/host/extensions/transcript/upgrade-recreate-resume.ts:241-333`](../../refs/grok-bot-0.18-reconstructed/source/host/extensions/transcript/upgrade-recreate-resume.ts#L241-L333)

Conversation-blob GC is reconstructed and is separate from box lifecycle. ## 2. The box protocol

### Host gateway versus exec-daemon RPC

There are two distinct protocols:

1. **Desktop coordinator ↔ in-box host:** HTTP JSON commands at `POST /api/<method>` plus an authenticated `GET /events` SSE stream. The host also serves `/health`, avatar reads, prepare-upgrade, local-exec request/response bridges, and WebAuthn bridges. [`source/shared/gateway-wire.ts:1-9`](../../refs/grok-bot-0.18-reconstructed/source/shared/gateway-wire.ts#L1-L9) [`source/host/gateway-server.ts:27-57`](../../refs/grok-bot-0.18-reconstructed/source/host/gateway-server.ts#L27-L57)
2. **In-box host ↔ box-exec-daemon:** Connect RPC over HTTP/1.1, binary protobuf, normally at `http://127.0.0.1:1337`, with `Authorization: Bearer <exec-token>` and optional display-owner headers. [`source/host/box/box-remote-accessor.ts:32-39`](../../refs/grok-bot-0.18-reconstructed/source/host/box/box-remote-accessor.ts#L32-L39) [`source/host/box/box-remote-accessor.ts:139-160`](../../refs/grok-bot-0.18-reconstructed/source/host/box/box-remote-accessor.ts#L139-L160) [`source/host/box/loopback-sand-box.ts:12-20`](../../refs/grok-bot-0.18-reconstructed/source/host/box/loopback-sand-box.ts#L12-L20)

The host gateway authenticates bearer tokens with constant-time comparison, rejects browser-origin requests, and permits unauthenticated mode only when reached through a loopback host header. Non-loopback binds automatically require a token; TLS is optional via cert/key environment variables. [`source/host/gateway-server.ts:21-23`](../../refs/grok-bot-0.18-reconstructed/source/host/gateway-server.ts#L21-L23) [`source/host/gateway-config.ts:25-54`](../../refs/grok-bot-0.18-reconstructed/source/host/gateway-config.ts#L25-L54)

### What is implemented in the reconstructed standalone daemon

The standalone daemon in `source/box-exec-daemon` is deliberately a partial loopback implementation, not proof of the complete shipped in-image daemon. It implements ping, capability reporting, environment replacement/update, a no-op MCP-load response, and one server-streaming Exec route. It reports `computerUseSupported: false` and `installPluginArtifactSupported: false`. [`source/box-exec-daemon/server.ts:450-485`](../../refs/grok-bot-0.18-reconstructed/source/box-exec-daemon/server.ts#L450-L485)

Its Exec switch implements file read, foreground shell, shell stream, background-shell spawn, and stdin writes; every other generated message case returns `BOX_EXEC_UNSUPPORTED`. Paths are constrained to the configured workspace and terminal roots, and symlink reads are rejected. [`source/box-exec-daemon/server.ts:179-219`](../../refs/grok-bot-0.18-reconstructed/source/box-exec-daemon/server.ts#L179-L219) [`source/box-exec-daemon/server.ts:221-263`](../../refs/grok-bot-0.18-reconstructed/source/box-exec-daemon/server.ts#L221-L263)

Shell commands run as `/bin/sh -lc` in detached process groups; foreground timeout/abort sends SIGTERM to the group. Background output is appended to terminal files with front matter and an exit footer, and stdin addresses a daemon-local shell ID. ### Avoid or simplify: hosted multi-tenant/product-specific choices

- **Do not copy the one-box-many-agents design if the goal is one whole machine per T3 thread.** Grok Bot’s shared box, workspace, and fork displays optimize hosted utilization, but weaken kernel/filesystem isolation and complicate ownership. - **Avoid shipping an exec protocol much broader than the daemon implementation.** Negotiate capabilities and reject unsupported tools before a turn rather than discovering support at execution time.
